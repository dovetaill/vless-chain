# Chain Panel 使用说明

在网页创建代理、选择中转路径，然后复制到客户端。登录后默认进入「代理」列表。

## 安装与登录

```bash
curl -fsSL https://raw.githubusercontent.com/dovetaill/vless-chain/main/scripts/install-server.sh | sudo bash
```

安装需要 Linux、systemd，支持 x86_64 / aarch64；推荐 Ubuntu 22.04+ / Debian 12+。安装脚本下载正式 Release，开发中的界面与功能需使用对应源码构建，见[高级部署与开发](docs/advanced.md#构建)。

保存安装结束时显示的控制台地址和管理员密钥。填写面板域名可配置 Nginx、HTTPS 与证书续期；公网登录请使用 HTTPS。Passkey 需要固定 HTTPS 域名，本机开发可用 `http://localhost`。

## 创建代理

1. 点击「创建代理」。
2. 选择入口服务器和客户端协议，名称与监听端口可留空自动生成。
3. 默认从入口直接出网，需要中转时修改「出网」。
4. 保存并应用，等待成功后使用「分享」。

| 协议 | 设置 |
| --- | --- |
| VLESS | REALITY + Vision，或 TLS + Vision；自动生成 UUID |
| Shadowsocks 2022 | 自动生成密钥，使用 `2022-blake3-aes-128-gcm` |
| Trojan | TLS，需要域名和证书，密码可自动生成 |
| HTTP / SOCKS5 | 用户名密码；普通入口不加密 |

TLS 模式可自动申请证书，也可填写自己的 PEM 证书链与私钥。REALITY 使用服务器的伪装站点设置，无需自己的证书。

## 本机与远程服务器

正常安装会接入控制台所在的服务器，创建代理时直接选择它；这里的本机是运行控制台的服务器。

添加远程服务器可在创建过程中操作，也可进入「服务器」页面：

1. 填写服务器名称、公网 IP 或域名。
2. 填写 SSH 端口，选择 root 密码或无口令私钥。
3. 点击「验证服务器」，核对并信任 SSH 指纹。
4. 确认远程服务器能访问控制台连接地址，点击「安装并连接」。

网页显示安装进度，服务器上线后即可创建代理。SSH 凭据只用于当次安装；日常配置通过已安装的服务同步。

没有本机记录时，创建过程中填写本机公网 IP 或域名即可启用。已有系统服务直接复用；网页启用的本机进程随控制台运行，不额外授予系统权限。

## 设置中转与出口

例如「客户端 → 香港入口 → 日本出口 → 互联网」：在代理编辑中展开「出网」，把「出口」选为日本服务器。需要更多跳时点击「添加中转」，按流量顺序选择服务器；页面显示完整路径。

已有其他平台创建的代理，可在「服务器」中「导入已有代理」，粘贴分享链接，再选作出口。导入不会接管对方服务器。

如果购买了端口中转，在「使用购买的中转入口」填写服务商地址和端口；平台保留原代理凭据与安全参数。服务商侧仍须把该端口映射到你的入口。

## 导入 Mihomo / Clash 客户端

代理应用成功后点击「分享」：

- **Mihomo 节点**：复制单条节点 YAML，或下载 `proxy.yaml`，合并到已有配置的 `proxies` 列表，并加入所需策略组。
- **链接 / 二维码**：复制分享链接，或用支持相应协议的客户端扫码。二维码在浏览器本地生成。

节点 YAML 只包含这一条代理，不包含客户端监听端口、DNS、规则或策略组。请使用支持相应协议的 Mihomo / Clash Meta 客户端；分享内容含连接凭据，妥善保存。草稿、停用和已删除的代理不能作为可用节点导出。

## 端口转发

「端口转发」→「创建转发」，选择入口服务器、监听端口、目标地址与目标端口，再选择 TCP、UDP 或两者。例如 `A:20000 → B:3306`，保存并应用后直接使用原业务客户端连接入口。

目标需从最后一台转发服务器可达；`127.0.0.1` 指该服务器自身。端口转发也可选择出口与中转，不需要客户端代理账号。

## 使用限制与排错

自动证书要求域名解析正确、TCP 80 可由节点服务使用；已有 Nginx 占用 80 时，使用自己的证书或另一台服务器，不会接管现有 Nginx。业务端口与中转端口需放行系统防火墙和云安全组，端口转发不自动解决 NAT 穿透。

外部代理仅支持已实现的链接组合，不支持的传输或插件会报错。检查失败时先看服务器在线状态与应用结果，再核对端口、证书、目标可达性和客户端协议支持；修改路径或协议可能让共享服务器上的连接短暂重连，应用失败会尝试恢复旧配置。

无法登录时可在控制台服务器运行 `sudo chainctl token` 查看密钥，或运行 `sudo chainctl reset-auth` 重置 TOTP / Passkey，保留代理配置。更多部署细节见[高级文档](docs/advanced.md)。
