# Chain Panel 使用说明

网站首页为客户公共查询页，可凭代理配置查询用量、余量和到期情况；原有 `/query` 私密查询链接继续可用。管理后台位于 `/admin`，也可从首页点击「管理登录」进入。管理员登录后默认进入「总览」，可创建代理、选择落地路径，并查看服务器资源和逐代理的用量、余量、网速、到期与报价。

## 安装与登录

```bash
curl -fsSL https://raw.githubusercontent.com/dovetaill/vless-chain/main/scripts/install-server.sh | sudo sh
```

正式发行包支持 Linux（systemd / OpenRC）的 x86_64 / ARM64，以及 macOS 14+ 的 Apple Silicon（ARM64）；不再提供 macOS Intel 包。Linux 发行包使用静态 musl，兼容 Alpine 与 glibc 系统；仍需 Python 3.10+ 及包含 Nginx/Certbot 的软件源。macOS 需先安装 Homebrew，并从普通管理员账户通过 sudo 执行。Windows 暂不支持。安装脚本下载正式 Release；本次跨平台包发布前需从源码构建对应平台包，开发中的界面与功能需使用对应源码构建，见[高级部署与开发](docs/advanced.md#构建)。

保存安装结束时显示的控制台地址和管理员密钥。填写面板域名可配置 Nginx、HTTPS 与证书续期；公网登录请使用 HTTPS。Passkey 需要固定 HTTPS 域名，本机开发可用 `http://localhost`。

## 总览与出租管理

「总览」展示服务器 CPU、内存、根目录所在磁盘占用、网卡收发速率，以及代理的周期用量、剩余额度、上传/下载速度、到期和下次重置时间。服务器网卡数据包含该机器的其他流量，不等于代理的计费用量；首次采样、离线或尚无统计时不会把未知网速当作实际零速率。

每条代理独立设置客户、额度、有效期和报价；同一客户的多条代理不共享额度。运营方使用管理后台，客户没有登录账号，收款由运营方在线下确认，当前不提供在线支付。

1. 在「客户与收款」创建客户档案，填写名称、联系方式和内部备注。
2. 创建代理后，在「出租信息」选择客户，填写月付、季付、年付报价；金额为人民币，留空关闭对应档位。出租信息保存后，首次开通前不能使用该代理。
3. 收到款项后，在「收款 / 续费」选择周期，逐条登记实收金额和备注，再确认开通或续费。实收可与当前报价不同，收款记录保留当次实收金额，可查看开通、续费和重新开通的历史记录；修改报价不改变已有期限和用量。
4. 在「客户与收款」设置统一续费联系入口，所有客户查询页使用这一联系方式。

期限和流量周期按北京时间计算。首次收款从开通时刻起算，每隔一个自然月重置额度；月末缺少同一日期时取当月最后一天，并保留原锚日，例如 1 月 31 日开通，依次在 2 月末、3 月 31 日重置。季付、年付也逐月重置额度。有效期内续费延长原租期，不清零当前用量；过期后重新开通从本次时间起算新周期并恢复满额。续费不会解除手动停用。

自用代理可在更多操作或批量操作中选择「设为无限期（自用）」。无限期仅取消到期限制，不登记收款，也不改变额度、限速或手动停用；已有周期保留，首次开通则从操作时刻开始按月计算。未分配客户的普通自用代理也没有到期限制，其月额度按北京时间自然月重置。

## 流量计量与运营操作

所有受管代理统一在成功鉴权后的转发通道计量业务载荷，上传与下载合计扣除额度。连接握手、外层协议封装、错误凭据和网站回落流量不扣代理额度；计数不代表目标网站已成功接收数据。TCP 只允许剩余额度内的载荷通过，UDP 剩余额度不足整包时拒绝该包。多个连接和 TCP/UDP 共用该代理额度，上传、下载分别共享方向限速。

SOCKS5 的 UDP 转发由成功鉴权的 TCP `UDP ASSOCIATE` 创建独立动态中继端口，客户端使用回复中的端口，TCP 连接关闭后中继也关闭。部署时需放行系统临时端口范围内的 UDP 入站；程序不会修改防火墙。中继只接收鉴权连接的来源 IP，并锁定首个有效 UDP 包的源端口。原生 SOCKS5 UDP 包不携带密码，不能视为逐包密码认证；首包锁定前，同 IP 且获知中继端口的客户端仍可能抢占关联。

额度用尽、到期或手动停用会在 Agent 本地阻断该代理并关闭已有转发连接，不依赖控制台持续在线。到额时，已获准的最后一块载荷最多有 5 秒完成提交和发送，随后关闭连接；对端不读或网络失败时不能保证送达。到期和手动停用立即关闭，不等待收尾。额度周期重置或续费后，在仍有效且未手动停用的情况下恢复使用。调整额度不清零当前用量，调高到足够额度可恢复超额代理。

在代理列表操作启停、额度、限速、无限期和开通续费，保存后立即安排下发，只更新所选代理的运营设置；不会夹带其他尚未应用的协议或路径草稿。在线节点确认后显示「已同步」，离线节点显示「等待同步」，恢复连接后再应用；保存成功不等于节点已生效。删除会重新生成受影响节点配置，同机其他代理可能短暂重连；被其他链式代理引用的代理需要先处理引用。

Agent 对已读入的鉴权业务载荷先提交本地 `traffic.db` 账本，再允许转发；账本使用 SQLite WAL 和 FULL 同步写入，并发更新可合并提交，提交失败则拒绝转发。`traffic.json` 仅是兼容统计快照，重启以数据库为准，首次升级会一次性导入已有快照。进程被强制终止不会回退已成功转发的计量；若终止发生在账本提交与网络发送之间，已计入的载荷可能尚未抵达目标，不会为尚未读到的未来流量预扣额度。耐久性依赖文件系统和存储正确执行同步写入。

备份和恢复应在停止 Agent 后包含完整 Agent 数据目录；`traffic.db` 与仍存在的 `traffic.db-wal` 共同组成权威账本，不能仅复制数据库主文件或用旧 `traffic.json` 替代。进程强杀恢复测试不等同于实际硬件断电测试。

受管核心异常退出时，Agent 会关闭所属运行组件并以失败状态退出。标准安装的 systemd 服务随后按 `Restart=on-failure` 重启 Agent，恢复已应用配置和持久账本，无需重新发布；独立运行 Agent 时需由其进程主管负责重启。

标准安装为 `chain-agent` 设置 `LimitNOFILE=65536`，为并发代理连接及仍存活的 UDP 关联提供文件描述符容量。

## 搜索与批量操作

「我的代理」支持按名称、客户、服务器、地址或端口搜索，并按协议、状态、7 天内到期、剩余不超过 10% 筛选。勾选表头可选择全部筛选结果；改变筛选条件会清空选择。

选中后可批量启用、停用、登记收款续费、设为无限期、调整额度和限速、导出或删除。批量续费需各代理均已设置客户和报价，并有共同开放的付费周期；每条代理的实收金额分别登记。批量调整的三个限制值会整体替换所选代理，留空表示不限。

## 客户免登录查询

客户打开面板地址下的 `/query`，粘贴本平台签发的分享链接、Mihomo 单节点或整份配置，即可查询对应代理的用量、余量、查询时网速、期限、报价和同步状态。整份配置只检查 `proxies` 中实际包含的节点，单次最多 100 个；不会获取 `proxy-providers` 链接，也不能查询其他服务商的额度。

免登录仍需证明持有代理：系统匹配端点和配置中的凭据，只返回成功匹配且纳入租赁管理的已应用代理。持有一条配置不会获得同客户其他代理、客户联系方式、内部备注或收款记录；到期或停用后仍可查询，删除后不可查询。

运营方也可为单条代理生成「客户私密查询链接」。持有链接即可只读查询该条代理；重新生成使旧链接失效，不改变代理连接凭据。客户可复制续费信息，通过页面展示的统一联系入口找运营方，付款后由运营方登记续费。配置和私密链接都应只交给该代理的使用者。

## 创建代理

1. 点击「新建代理」。本机就是入口，无需选择服务器。
2. 选择协议，确认本机 IP 或域名；名称、端口和凭据可以自动生成。
3. 默认直接出网；需要链式代理时，按顺序选择落地。
4. 点击「创建代理」，等待应用成功后复制分享链接或 Mihomo 节点。

| 协议 | 设置 |
| --- | --- |
| VLESS | REALITY + Vision、TLS + Vision、REALITY + XHTTP、TLS + XHTTP；默认 REALITY + Vision |
| Shadowsocks 2022 | 自动生成密钥，使用 `2022-blake3-aes-128-gcm` |
| Trojan | TLS，需要域名和证书，密码可自动生成 |
| VMess AEAD | TCP，alterId 为 0；域名默认使用 TLS，自动生成 UUID |
| Hysteria 2 | QUIC + TLS，需要证书，自动生成认证密码；放行 UDP 监听端口 |
| TUIC v5 | QUIC + TLS，需要证书，自动生成 UUID 和密码；放行 UDP 监听端口 |
| HTTP / SOCKS5 | 用户名密码；普通入口不加密 |

TLS 模式可自动申请证书，也可填写自己的 PEM 证书链与私钥。REALITY 无需申请自己的证书：在表单填写目标地址（域名/IP 加端口）和该目标证书覆盖的 SNI。「检测目标与 SNI」从控制台所在机器检查 TLS 1.3、证书/SNI、H2 和耗时；检查通过不等于所有客户端网络均可达。

Hysteria 2、TUIC v5 接入及包含 TUIC、Hysteria 2、Shadowsocks 或 HTTPS 的出网链由发行包内的 Mihomo 内核运行，随 Agent 启停；每条链独立配置连接路径，仍使用面板的流量统计、限速和出网链路。其他接入协议使用 Xray。升级时需同时更新控制台与 Agent。当前 Xray 的 REALITY 启动包含目标采样，Agent 为此预留 6 秒再开放入口；这不代替目标可用性检查，目标网络异常仍会导致连接失败。

### 一次创建多种 VLESS 组合

勾选「一次创建多种组合」，选择所需组合。默认分别分配端口；TLS 组合需要解析到本机的域名和有效证书。批量保存是原子的，任意一条无效时不保存其他条。应用成功后在列表逐条点击「分享」，取得对应链接、二维码或 Mihomo 节点。

XHTTP 可设置路径、Host 和模式；其分享配置不带 Vision 的 `flow`。REALITY 组合包含公钥、short-id 和所选 SNI。批量创建沿用同一组 REALITY 目标/SNI 和 TLS 域名。

### 网站回落与统一 443

TCP + TLS + Vision 可在「TLS 网站回落」填写 `builtin` 显示内置主页，或填写自己的 HTTP/HTTPS 网站地址；留空关闭。普通浏览器使用该代理域名访问同一端口即可看到网站。REALITY 的非认证连接由 Xray 交给所选目标网站；这里的 TLS 网站回落不用于 XHTTP。

本机已有 Nginx HTTPS 网站时，先安装包含此功能的控制台及 Agent，在服务器执行：

```bash
sudo chainctl ingress-enable
```

也可在 `chainctl` 菜单选择「启用统一 443」。随后展开代理表单的监听端口，勾选「使用统一 443 入口」。Nginx 使用 `ssl_preread` 读取 SNI，不解密代理 TLS；已存在的网站转到本机内部 TLS 端口，继续使用原证书和站点配置，并通过 PROXY protocol 保留客户端 IP。TCP 80 的证书验证及 UDP 443 不迁移。

每个 SNI 对应一个入口。REALITY 与 TLS 可以使用不同 SNI 共用 443；同一个 SNI 的 TCP 和 XHTTP 请使用独立端口，或分别创建并填写不同 SNI。不能使用现有网站的域名抢占它的入口。

自动接管支持系统 Nginx 的普通 IPv4 HTTPS 监听（及其 IPv6 监听）；已有 `stream`、自定义真实 IP 信任配置、指定 IP 的 443 绑定会明确拒绝，避免覆盖。缺少 stream 模块时由系统软件包安装。启用前保存配置，校验或重载失败恢复原文件；后续手工修改受管文件会阻止自动恢复，需先核对差异。

先停用或改回独立端口并应用共享入口代理，再执行 `sudo chainctl ingress-disable` 恢复原 Nginx 监听。正在使用共享入口时关闭分流会使这些代理断开。

## 本机与外部代理

### 多机总控与监控告警

总控默认展示全局状态与短时网卡速率趋势；VPS、代理、外部代理和维护任务分别分页，每页 20 条。搜索、筛选不清除跨页选择，批量确认会列出实际 VPS 与代理范围；失联或不支持维护的目标需先修复或调整选择。编辑代理在宽侧栏内完成，外部代理在弹窗内编辑，保留筛选与列表位置。保存配置后预览并确认应用；关闭预览时配置仍保留，本会话可直接点击“继续应用”，刷新页面后可从 VPS 详情继续应用。各列表保留标签切换前的筛选与页码，手机采用卡片布局。

总控约每 30 秒同步远端，页面每 5 秒读取缓存；超过 90 秒的采样显示未知，并展示有效数据覆盖率。网卡速率包含全部业务，代理用量按各代理当前周期合计，跨 VPS 链路不去重，不等于运营商账单。趋势只保留当前页面会话最近 10 分钟，刷新页面后重新积累；外部代理没有独立速率采样。实现与验收范围见 [交互改造方案](FLEET-UX-PLAN.md)。

“多机总控”用于统一管理多个已经安装本平台的独立 VPS 面板；各 VPS 保留自己的数据库、代理与 Agent，总控离线不影响已运行的代理。一个远端面板只能授权一个总控，不支持多级总控或接入自己。

1. 首先在总控与各 VPS 手工安装包含此功能的版本。远端面板必须使用有效 HTTPS；本功能不会自动部署现有机器。
2. 在远端“多机总控 → 总控设置”生成接入码，在总控的同一设置页填写远端名称、HTTPS 根地址与接入码。接入码有效期 10 分钟且只能使用一次。绑定授予代理管理、固定维护操作与管理员免密跳转权限，应仅交给可信的总控。
3. 总控汇总代理、外部代理和状态；同名资源按所属 VPS 区分。“管理代理／外部代理”在总控内操作对应远端，沿用已有编辑、应用与影响范围确认。外部代理可原地编辑，保留引用 ID。客户、收款与订阅不合并，跨面板落地仍通过导入分享链接配置。
4. “免密进入面板”使用 60 秒内有效的一次性票据，票据放在 URL 片段中，兑换后立即从地址栏移除；不会传递长期管理员密钥。远端解除授权会撤销尚未兑换的票据和已产生的委托会话。总控解除接入要求远端在线确认；远端失联时可在远端恢复后本地解除授权。
5. 在“监控告警”配置本地检测策略及 Telegram、SMTP。邮件只使用直接 TLS 或 STARTTLS，不支持明文 SMTP。秘密字段留空表示保留，清除需显式勾选。通知发送失败会退避重试，并在记录中显示错误；外部渠道响应丢失时仍可能重复投递。

监控默认关闭，保存策略时勾选启用。默认每 300 秒检查已应用且有效的代理，3 次连续失败报警、2 次成功通知恢复；Agent／面板失联 60 秒报警。总控同时检测远端公网入口，远端检测本机整链，结果分别展示；一次 HTTP(S) 成功不代表 UDP、全部客户端网络或所有目标正常。自动探测最多与远端同步共用 8 个并发任务，任务分批调度；负载过高时检测可能延后，探测会产生少量代理计费流量。

额度按 80%、95%、耗尽提醒，每周期每档一次；租期与已上报的代理 TLS 证书按剩余 7、3、1、0 天提醒；证书续期失败也单独记录。手动停用、未开通、到期、额度耗尽的代理不进行网络故障检测。持续故障默认每 24 小时提醒一次。告警和检测状态保存在数据库，最近通知保留 500 条（界面及每次同步显示最近 100 条）。长时间失联且产生大量事件时，超过保留上限的通知无法补发。

总控可整套覆盖所有已接入 VPS 的监控策略；远端保留自己的配置并显示当前生效来源。覆盖经同步后生效，总控失联时继续执行最后收到的策略；取消覆盖或解除授权后恢复本地策略。已接入面板的通知由总控统一发送；总控宕机期间远端继续保存检测记录，但不会自行接管外部通知。

批量维护首版仅支持 Linux systemd。首次手工更新会安装 `chain-maintenance.socket/service`，面板仍使用原有非 root 身份；受限执行组件校验调用进程 UID，只接受正式版本升级、面板／Agent 重启和任务查询，不接受 Shell、任意路径或任意下载地址。任务 ID 持久化，同一 ID 不重复执行；组件中断的任务标记“结果待确认”，不会自动重放。

进入多机总控时自动获取 GitHub 最新正式发行版本，也可点击“检查最新版本”刷新，无需手填版本号；升级前核对包含的 Xray、Mihomo 版本。VPS 列表分别展示面板与本机 Agent 最近上报的版本，不一致时提示；旧 Agent 未上报版本时显示未知，不推定与面板一致。总控逐台执行整套升级，逐组件显示结果；随后核对 Agent 心跳和可用代理的公网整链。失败或长期无法确认时暂停剩余机器，已成功机器不自动回退；先确认实际状态，再仅选择需重试的机器提交新任务。升级和重启 Agent 会中断连接。安装器的失败恢复保留原有机制，数据库不自动回退，也不允许远程自动降级。批量启停代理属于配置下发，是否已生效仍以代理的同步状态为准。

维护任务数据存放于 `/var/lib/chain-maintenance`（root:root、0700），控制 socket 为 root:chain-panel、0660。普通卸载保留维护历史，清除数据卸载会核验归属后删除；这些权限只由明确安装流程创建，不由 Web 请求修改既有生产目录权限。

每个 Web 页脚显示面板版本，“设置 → 版本与维护”展示本机面板、Agent 最近上报版本及发行包的 Xray/Mihomo 版本，可升级到最新正式 Release 或整套重启。升级自动更新并重启已安装的面板与 Agent，保留 Agent 原接入关系；项目独立 HTTPS 服务存在且归属匹配时也会自动重启。Agent 同时重启其代理内核，共享 Nginx 仅沿用安装流程所需的配置重载，不重启宿主机或强制执行证书续期。总控提供逐台整套重启，旧 VPS 须先升级到支持该动作的版本。升级期间无需另点重启；页面保存任务 ID，重新登录后回到设置继续查询原任务，不重复提交。网页维护仅支持 Linux systemd；未安装维护组件或其他平台会显示原因。失败保留逐组件结果，现有恢复机制不回退业务数据库。

手工验收请使用两台备用 VPS，A 为总控、B 为远端，均安装包含上述功能的版本并配置有效 HTTPS：

1. 在 B 生成接入码，在 A 接入 B。等待约 30 秒同步，核对所属 VPS、代理、外部代理和版本；重复使用接入码应失败。
2. 从 A 管理 B，新建、编辑、删除专用测试代理和外部代理，同时在 B 核对结果。应用测试代理后用客户端验证出网；先选一条测试代理验证批量停用／启用及实际连接结果。
3. B 本地检测间隔设为 300 秒，A 总控覆盖设为 60 秒。等待同步，B 应显示有效间隔 60 秒且本地配置仍为 300 秒；取消覆盖后恢复 300 秒。
4. 在 A 配置 Telegram、邮件并发送测试通知，核对实际收件和发送记录。启用监控，用独立测试线路及可控检测目标制造失败：连续 3 次失败才报警，随后恢复目标，连续 2 次成功通知恢复。检测间隔和调度耗时会影响等待时间；不要修改正在使用的线路来造故障。
5. 仅在备用 B 上停止面板服务，保持 Agent 运行；默认失联阈值 60 秒，加上约 30 秒轮询后，A 应告警且不持续刷屏。恢复面板，A 应通知恢复。再单独测试 Agent 停止／恢复，确认对应告警。
6. 从 A 免密进入 B，复制该链接再次打开应失效。B 解除授权后，该委托会话也应失效，B 原有独立管理员会话仍可用，检测策略恢复本地配置。
7. 重新绑定后重启备用 A、B，核对服务自启动、绑定与配置保留，以及代理实际出网。关闭 A 时 B 应能独立管理，代理继续工作。
8. 最后在备用机验收批量维护：核对目标发行版、先升级一台，检查面板／Agent／内核版本和实际出网，再扩至多台。模拟首台失败时后续机器应暂停；结果未知时先查询原任务，不反复新建升级任务。

`tests/fleet-two-panels.py` 用两个独立面板进程验证 HTTPS 接入、远程 CRUD、定时同步、策略覆盖、失联／恢复记录、重启持久化及解绑。它要求非 root 身份、独占临时目录，以及仅在隔离测试构建中信任的本机测试证书；不会启动 Agent、代理内核或维护服务，也不外发通知。因此它不能替代上述真实出网、渠道收件、系统开机和升级验收。

安装自动接入控制台所在机器；本机记录缺失时，创建流程会恢复安装器保存的身份，无需额外添加服务器。旧安装缺少恢复信息时先执行 `sudo chainctl update`。

其他机器请自行通过 SSH 登录并运行安装命令，在对应面板创建代理后复制链接。「外部代理」只管理现有代理链接，不保存 SSH 凭据，也不执行远程安装。

点击「导入外部代理」，可粘贴协议分享链接、Mihomo / Clash 单节点 YAML 或 JSON，支持单对象、单元素列表和只有一条节点的 `proxies:` 列表。名称可自动读取；导入后「链接 / Mihomo」提供两种格式。

## 链式代理

例如「客户端 → 本机 → 落地 A → 落地 B → 互联网」：新建或编辑代理，选择「链式代理」，依次选择 A、B。可选择外部代理或其他已启用、已应用的本机代理；禁止循环引用。可以同时创建多条独立本机代理，各自使用不同端口和路径。

HTTP/HTTPS 出口仅支持 TCP；经它连接 Shadowsocks 或 SOCKS5 时也不支持 UDP。VLESS、VMess、Trojan 可通过 TCP 隧道传递 UDP。Hysteria 2、TUIC 连接本身需要 UDP，前置路径不支持 UDP 时会拒绝保存，不能靠换证书或打开客户端 UDP 开关解决。

分享和订阅会按整条路径（含本机代理引用）标记 UDP 能力；仅支持 TCP 的节点导出 `udp: false`，导入后也会保留此限制。

当前 Mihomo 的 Hysteria 2 实现限制单个 UDP 数据报为 4096 字节，后续 UDP 协议的封装也计入此上限。因此 Hysteria 2 → SS2022（本项目默认 AES-128、IPv4 目标）双向业务载荷上限为 4038 字节，Hysteria 2 → SOCKS5（IPv4 目标）为 4086 字节；地址格式、加密算法或更多封装会改变可用大小。超限数据报会丢弃，`udp: true` 不代表支持任意大小的数据报。这是[当前内核限制](https://github.com/MetaCubeX/sing-quic/blob/1c242664697a/hysteria2/internal/protocol/proxy.go#L25)，不是可通过面板开关提高的额度。

修改或删除被引用的代理前先处理引用关系。端口转发和购买中转入口功能已移除。

## 导入 Mihomo / Clash 客户端

代理应用成功后点击「分享」：

- **Mihomo 节点**：复制单条节点 YAML，或下载 `proxy.yaml`，合并到已有配置的 `proxies` 列表，并加入所需策略组。
- **链接 / 二维码**：复制分享链接，或用支持相应协议的客户端扫码。二维码在浏览器本地生成。

节点 YAML 只包含这一条代理，不包含客户端监听端口、DNS、规则或策略组。请使用支持相应协议的 Mihomo / Clash Meta 客户端；分享内容含连接凭据，妥善保存。草稿、停用和已删除的代理不能作为可用节点导出。

## 使用限制与排错

安装器安装 Nginx 和 Certbot，由 Nginx 提供 TCP 80 证书验证；Agent 不再争用 80 端口。域名需解析到本机，TCP 80 和代理监听端口需放行系统防火墙及云安全组。已有同域名站点必须能提供 ACME 验证路径，否则申请失败会显示具体错误，不会显示创建成功。

外部代理仅支持已实现的链接组合，不支持的传输或插件会报错。检查失败时先看服务器在线状态与应用结果，再核对端口、证书、目标可达性和客户端协议支持；修改路径或协议可能让共享服务器上的连接短暂重连，应用失败会尝试恢复旧配置。

无法登录时可在控制台服务器运行 `sudo chainctl token` 查看密钥，或运行 `sudo chainctl reset-auth` 重置 TOTP / Passkey，保留代理配置。更多部署细节见[高级文档](docs/advanced.md)。
