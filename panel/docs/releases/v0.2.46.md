# v0.2.46

- 修复将 HTTP 301/302 正常跳转误判为代理连接失败的问题。整链探测和出口分段检查均最多跟随 5 次跳转，仍限制总耗时；跳转循环、最终 HTTP 错误和握手失败继续报告失败。
- VPS 详情与代理列表提供“立即复查”。使用当前监控网址的完整 HTTP 检测会更新同一条监控记录和恢复计数，并立即刷新远端快照；TCP 检查、其他检测网址、过期结果或已改变的线路不能清除原告警。连续恢复次数仍按既有策略执行，页面显示确认进度。
- 修复代理列表显示最近失败、VPS 却仍仅显示“在线”的矛盾。尚未达到连续失败告警阈值时，VPS 显示“连接检测待确认”；自动复查保持启用，无需日常手动操作。
- 维护任务提供“立即复查连接”，只将对应 VPS 的连接检查提前排队，不重做升级或恢复其他未执行操作。组件维护完成但验证未完成时，总状态显示“维护完成 · 连接待确认”；验证通过后展示新验证结果。
- 短暂的 Xray 探测进程保存经过脱敏的详细日志，让连接重置能显示具体握手错误；运行中代理的日志级别和配置不变。

验证：12 项总控测试、7 项监控测试通过；使用真实 Xray 的隔离回归验证了跳转成功、跳转循环失败、最终 HTTP 503 失败，以及出口分段检查跟随跳转。TypeScript 检查、前端状态断言、前端构建与两组模拟 API 的浏览器回归通过，覆盖立即复查、恢复计数、任务复查不重复升级和自动移入历史。本地测试使用非特权身份与独占目录，进程及临时产物已清理；正式三平台构建与安装验证以本版本 Actions 为准。

## 升级与自测

先在总控执行 `sudo chainctl update`，再从总控将远端已安装组件升级至 `0.2.46`，刷新网页。总控负责公网入口验证，远端面板负责本机自动检查，Agent 负责出口分段检查，因此三者均需更新。

1. 使用会正常跳转的检测网址，例如 `https://google.com/`。可用线路应跟随跳转取得最终成功响应，不再仅因 301 显示失败。
2. 日常等待自动复查即可。默认检测间隔 300 秒、连续恢复 2 次，已有告警可能需要两轮成功才解除，另加排队和检测耗时；期间显示恢复确认进度。
3. 需要立即查看时，在“所有代理”行内或“查看 VPS”的异常旁点击“立即复查”。结果、时间和恢复进度应立即更新。单次通过但未满足恢复次数时，不会伪造完全恢复。
4. 在维护任务中点击“立即复查连接”，应显示等待连接复查，随后更新后续验证；组件版本和升级次数不变。全部验证通过后，任务自动移入历史。
5. 首次检测失败但尚未达到告警阈值时，VPS 应显示“连接检测待确认”，不会同时给出无异常的“在线”状态。

真实 REALITY 握手失败仍会保留证据；本版本不会自动更改 SNI、目标、UUID 或密钥。若更换 REALITY 目标和 SNI，客户端订阅也需同步更新。
