# v0.2.44

- 自动检测结果显示实际入口地址、端口、SNI 和检测目标，保留脱敏后的失败原因，避免将某个入口失败误解为全部线路不可用。
- 本机代理检测持续失败时，系统自动让入口 Agent 检查已应用的出口及后续链路。出口通过会显示“入口检测异常，出口正常”，不要求用户寻找或触发手动检测，也不会将出口通过冒充整条连接恢复。
- 系统按现有策略自动复查。最近一次通过但尚未达到恢复次数时显示“入口恢复确认中”和进度，达到条件后自动解除告警；已停用、删除、到期或额度耗尽线路的当前检测告警自动清除，历史通知保留。失联线路不会被误当作已恢复。
- 总控的 VPS 概览和详情可展开“自动检测详情”，监控页显示“最近自动检测”；自动检测不重启现有代理，不修改客户端连接参数。

验证：6 项监控 Rust 测试、1 项覆盖三种协议的入口参数测试、TypeScript 检查、前端状态断言、前端构建及模拟 API 的浏览器自动恢复测试通过。测试使用非特权身份和独占临时目录，相关进程与产物已清理，未修改生产服务或权限。正式三平台构建、安装验证和附件发布结果以本版本 Actions 为准。

## 升级

在总控及需要升级的 VPS 分别执行，升级可能短暂重启对应服务，请选择维护时段：

```sh
sudo chainctl update
```

仅安装 Agent 的机器使用：

```sh
sudo chainctl update --component agent
```

更新后重新打开 `chainctl`，确认相关组件版本为 `0.2.44` 或更高，再刷新总控网页。仅升级总控不会替远端 VPS 升级其本机自动检测逻辑。

## 自测

1. 保持监控开启，进入总控的 VPS 详情，等待下一轮自动检测。已有持续失败告警应出现真实入口、端口、SNI、检测目标和失败原因；展开“自动检测详情”查看自动分段结果。无需点击检测、关闭监控或重启代理。
2. 如果出口及后续链路通过，应显示“入口检测异常，出口正常”；如果出口也失败，应保留对应错误，不应笼统宣布全部线路故障。
3. 故障实际恢复后，观察状态自动变为“入口恢复确认中”，达到恢复次数后告警自动消失。默认每 300 秒检测一次、连续通过 2 次解除，因此可能需要约 10 分钟，再加检测耗时和总控同步时间；以页面显示的实际策略为准。
4. 对已经停用或删除的线路，确认其旧检测告警不再保留在当前告警中，历史通知仍可查看。无需为此停用正在承载业务的线路。

此版本改善自动定位和告警恢复，不会自动修改 REALITY 的 SNI 等业务配置。真实入口仍未通过时会继续展示具体证据，不会强制清除仍然有效的告警。浏览器回归使用模拟数据，实际 VPS 链路需在升级后按上述步骤观察。
