# v0.2.48

- 推荐 Xray 更新为 `26.3.27-chain.1`。这是本项目补丁构建：固定官方 26.3.27 基线和依赖，只回移 XTLS/REALITY#33，将目标 TLS 握手记录缓冲从 8 KiB 扩至 17 KiB；保留原有客户端兼容性。不会修改 SNI、UUID、公私钥或订阅参数。
- 源码模块校验和与 Go 1.26.4 固定；二进制版本输出带 `chain.1-reality-buffer-17k`，发行包附带 `share/Xray-PATCHES.txt`，明确区分官方原版与本项目补丁。
- 单机“设置 → 版本与维护”和总控批量升级均可选择本次 Xray 来源。默认使用推荐稳定版；主动选择官方最新版时包含预发布，校验官方附件地址和 SHA256 后才替换临时安装包中的内核，仍沿用组件升级及失败恢复流程。新内核可能要求更新客户端，不会后台自动追新。
- 老 VPS 需先使用推荐稳定版升级维护组件；总控会阻止向旧执行器提交官方内核选项。任务保留所选来源，重试同一任务不能偷偷改变来源。

- 修正补丁内核发布构建：三平台显式安装 Go 1.26.4，并通过 Go 自带清理命令移除本次模块与工具链缓存。0.2.47 未通过发布检查，没有发布安装包。

验证：非特权隔离环境中，15,238 字节目标证书记录使原版 Xray 握手失败，补丁版完成认证与数据交换；Microsoft 目标返回 8,273 字节记录时补丁版也通过真实握手和数据交换。通过 2 项总控 Rust 定向测试、交付／维护／平台及升级回滚定向测试、TypeScript 检查、前端构建和维护页面浏览器回归，覆盖单机及批量来源选择、旧 VPS 能力限制、任务幂等、来源和校验失败拒绝替换。正式三平台构建、隔离大证书握手回归与安装验证由发布 Actions 执行，结果以 Actions 为准。

## 升级与自测

1. 总控及所有远端均升级到 `0.2.48`，保持“推荐稳定版”。面板、Agent 和其内核一起更新；只升级总控不会替换远端内核。
2. 在“版本与维护”确认 Xray 为 `26.3.27-chain.1`。命令行可运行 `/opt/chain/current-agent/bin/xray version`，输出应包含 `chain.1-reality-buffer-17k`。
3. 使用原客户端、原订阅连接；无需更换 Microsoft SNI。等待自动复查，或点击“立即复查”查看最新结果。已有告警仍按策略要求连续成功后解除，不直接删除失败证据。
4. 选择官方最新版：网页选择相应来源并确认升级，或执行 `sudo chainctl update --xray-channel latest --non-interactive`。这会重启组件，可能要求更新客户端。
5. 回到推荐内核：重新选择推荐稳定版升级，或执行 `sudo chainctl update --xray-channel recommended --non-interactive`。面板版本相同也可重新安装，业务数据不回退；纯 Agent 安装加 `--component agent`。

官方最新版选项只在明确选择时生效，下一次默认仍是推荐稳定版。Mihomo 保持 `1.19.32`。
