# v0.2.45

- 批量维护最多同时处理 5 台 VPS，按远端实际仍在执行的任务计数。单台安装失败或失联不会暂停其余机器；已完成的操作不再重复下发，继续核对时沿用原任务编号。
- 将组件维护与连接验证分开调度。升级成功立即计入“维护完成”，验证失败单独展示，后台按总控现有检测间隔自动复查，不重新安装组件，也不占用升级名额。
- 兼容旧版“维护成功、验证失败”的暂停记录，自动复查其连接结果。旧任务中尚未执行的升级不会自动恢复，以免重放旧版本操作；确需继续时使用“继续未执行任务”。
- 已完成且验证通过的任务自动移入历史，默认列表只显示待处理记录；列表直接提供“移入历史”，也可勾选“显示历史任务”查看原始结果。归档停止该任务后续自动复查，保留原始记录，不代表连接故障已修复。

验证：后端 11 项总控测试与 6 项监控测试通过，包含 100 台模拟升级、最多 5 台同时运行、首台失败后其余 99 台完成，以及自动复查不重复安装。TypeScript 检查、前端状态断言、前端构建和模拟 API 的管理页面浏览器回归通过，覆盖维护完成计数、自动恢复、历史隐藏和归档。全部本地验证使用非特权身份和任务独占目录，未调用真实 VPS 升级接口。正式三平台构建与安装验证以本版本 Actions 为准。

## 升级与自测

先在总控机器更新，升级会短暂重启相关服务：

```sh
sudo chainctl update
```

确认总控版本为 `0.2.45` 后刷新网页，再从 VPS 列表选择需要升级的机器并执行“批量升级”。本次调度修复在总控侧生效，远端已有 `0.2.44` 维护接口可继续使用。

1. 多选超过 5 台测试 VPS，确认最多同时维护 5 台，其余等待空位；某台失败时其余机器继续处理。生产自测不必人为制造故障。
2. 某台升级成功但连接验证失败时，“维护完成”应仍计入该机器，并显示“自动复查中”和下次复查时间，不应暂停整批升级。
3. 实际连接恢复后，等待自动复查，默认间隔 300 秒再加检测和排队耗时。验证通过后任务自动移出待处理列表，无需点击检测。
4. 对不再需要继续的旧暂停任务，点击列表中的“移入历史”，确认顶部提醒和默认列表都不再显示；勾选“显示历史任务”仍可查看记录。旧任务保留原目标版本，不要继续已经不需要的旧版升级；可移入历史后新建当前版本任务。

本版本修复批量维护流程，不会自动修改 REALITY 的 SNI、UUID 或出口配置。真实连接重置仍会显示具体错误，不能把组件升级成功当成链路已恢复。
