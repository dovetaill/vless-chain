# v0.2.4

修复本机 VLESS 创建时误选普通 TLS 的默认行为，并新增 VMess AEAD、Hysteria 2 和 TUIC v5。

- VLESS 无论填写 IP 还是域名，默认使用 TCP + REALITY + Vision；修改地址保留已选的安全模式，已有 TLS 线路仍按原配置运行。
- VMess 支持 TCP 和可选 TLS，使用 AEAD、alterId 为 0；Hysteria 2、TUIC v5 使用 QUIC + TLS，支持自动证书和手动证书。
- 新协议覆盖创建、协议分享链接、Mihomo 节点导入导出、连接诊断及链式代理。
- 发行包增加固定版本 Mihomo v1.19.32，并校验官方附件 SHA256。TUIC 接入及包含 TUIC 的外部代理链由 Agent 管理的 Mihomo 执行，其余接入协议继续使用 Xray。
- 修复 TUIC 自动证书目录的访问限制；启动时核对内核实际监听的端口，避免监听失败但进程存活时误报成功。

已验证：19 项 Rust 单元测试、前端类型检查与构建、浏览器创建和安全模式切换；VLESS REALITY、Shadowsocks 2022、Trojan、HTTPS 代理、SOCKS5、VMess TLS、Hysteria 2、TUIC v5 的正式节点均通过实际 HTTPS 请求，支持 UDP 的 7 种协议通过回显测试。另验证了 VMess 不加 TLS、分享链接与节点配置导入导出，以及 TUIC 位于 VLESS 前后时的 TCP/UDP 链路。自动证书目录及 TUIC 监听端口被占用的回归检查通过。

升级：`sudo chainctl update --component panel --non-interactive`。安装器管理的本机 Agent 会一起更新并重启，连接可能短暂中断。远程 Agent 需在各自机器上更新后再使用新协议。

兼容性：Hysteria 2、TUIC v5 需要客户端支持并放行对应 UDP 端口；VMess 目前支持 TCP 传输。不支持的传输或参数会明确报错，未验证所有客户端版本和运营商网络。
