# v0.2.67 Web 升级故障复现

本次使用 GitHub 正式发行的 Linux x86_64 v0.2.67 与 v0.2.71 附件，分别通过发行 SHA256SUMS 校验。测试发生于 2026-11-04 UTC，独占 Alpine 3.23 / OpenRC 容器内运行真实维护服务、面板、Agent 和 Chromium；未操作生产 VPS。

## 实际结果

| 步骤 | 实际入口 | 结果 |
| --- | --- | --- |
| v0.2.67 安装与心跳 | 正式包安装器 | 面板、Agent、维护服务启动 |
| Xray 26.10.31 安全更新 | 登录后的真实 `/api/federation/task`，非模拟响应 | EPERM，任务失败，Agent 被停用 |
| 已停用旧部署升级 0.2.71 | Chromium `/admin#settings`，点击“升级并重启” | 失败：请先完成内核升级验证或恢复安全版本 |
| 总控升级已停用旧部署 | Chromium `/admin#fleet` → VPS → 选择节点 → 批量升级 → 确认执行 | 同样失败；远端仍为 0.2.67 |
| 已停用部署程序恢复 | v0.2.71 包内 `chainctl update --package ... --non-interactive` | 完成，保留停用状态，旧维护 PID 1621 已退出，新维护 PID 2795 指向 0.2.71 |
| 恢复后的 Xray 更新 | 登录后的真实 `/api/federation/task` | 进入 `awaiting_verification`，停用状态清除，新 Agent 心跳版本 0.2.71、内核 26.10.31 |

任务证据：

- EPERM：`27aa9ade-19cc-4da2-8bc6-6b231fb8646e`，`Operation not permitted (os error 1)`。
- 设置页程序升级：`16c3716f-236a-4a6d-b54d-da8ab846c654`，目标 0.2.71，before/after 均为 0.2.67。
- 总控程序升级：`9b4d791b-dbe5-4198-b339-d8a3f2eab5f3`，同样被旧维护程序拒绝；总控回执同时出现 `maintenance_state=failed` 与 `verification.state=pending`。
- 恢复后的内核更新：`232f9519-1c49-47cb-a455-0f1684e2370d`，开始时间 1793754086，新心跳 1793754107；未代替用户确认实际传输。

## 结论与边界

已安全停用的 v0.2.67 无法通过上述两个 Web 入口直接升级程序。旧版 `Manager::update_checked` 明确拒绝 `core_blocked` 非空的部署；新版源码修正无法反向改变仍在执行的旧安装器。此次验证支持“使用新版安装器恢复程序，再更新内核”的恢复路径，不能称为旧版 Web 直接升级通过。

总控自签 HTTPS 接入失败后，使用真实配对接口获得令牌，并在测试总控数据库中设置回环 HTTP 地址，以隔离证书信任问题。升级按钮、任务下发、远端维护执行及回执均真实；该场景不覆盖 HTTPS 接入兼容性，也不覆盖三层总控。

本轮未配置业务线路，未覆盖统一 443 代理入口、客户原链接或 UDP 传输，也未执行生产 systemd 场景。不能以新心跳或空闲 Agent 存活认定客户业务恢复。未验证未停用旧部署的直接 Web 升级成功路径。本轮验证的是正式发行包，不包含工作区尚未发布的新增修复。

容器安装需要 SYS_PTRACE 以读取容器内不同 UID 的服务进程；未开放宿主 PID/网络命名空间、Docker socket、宿主系统目录或生产路径。安装和验证写入仅发生在容器及本次独占临时目录。未改生产属主或权限；没有对生产路径执行验证，故没有生产元数据前后对比结论。

清理：已停止容器内 Agent、面板、维护服务及测试总控、Nginx 进程组，删除容器与本次测试镜像；Chromium 会话已关闭。未向宿主发布端口，容器内 443、37243、37244 随网络命名空间销毁。已删除约 460 MB 临时目录，删除前检查无进程、工作目录或打开文件引用；保留本报告，未保留密钥、令牌、数据库及下载包。
