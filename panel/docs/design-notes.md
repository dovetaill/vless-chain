# 功能设计与参考

本项目支持个人代理管理及按条出租，由运营方维护客户、报价、期限和人工收款记录。以下保留已有产品参考，并说明当前实现的选择。

## 将用户任务与内部协议分开

GOST 将 HTTP 代理和固定 TCP 转发区分为不同服务类型，并独立表达后续转发链。[GOST 命令行模型](https://gost.run/reference/configuration/cmd)

本项目据此拆出「代理接入」「端口转发」「网站反代」三个入口。原有 Xray 继续承载代理与内部中转，表单不再要求普通端口转发用户先理解 VLESS。资源页区分自有服务器与外部端点；服务商出售的转发端口只是端点映射，不能被当成拥有系统管理权限的服务器。

## 整条线路的带宽上限

GOST 明确区分服务级限速与连接级限速，二者的限制范围不同。[GOST 限速限流](https://gost.run/concepts/limiter)

本项目在代理核心成功鉴权后接入逐线路的本地 SOCKS 计量桥，再交回原出网路径。同一线路的 TCP/UDP 和并发连接共享额度，上传与下载分别共享限速预算；TCP 按剩余额度放行，UDP 只放行额度足够的完整载荷。外层握手、协议封装、错误凭据和网站回落不扣额度。监控展示统计结果，Agent 本地执行传输限制，没有修改宿主机网卡队列，也没有额外引入 GOST 进程。

租赁额度按北京时间开通日逐月重置，月末取当月末日并保留原锚日。有效期内续费延长原租期、不清零用量，过期重开采用新锚点。无限期代理保留额度和手动启停限制。启停、期限、额度和限速在已应用配置上单独下发，不发布其他草稿；离线节点保留待同步状态。到期与周期重置由 Agent 本地执行。

计量桥只对已读入的业务载荷扣额，并等待 `traffic.db` 的 SQLite WAL/FULL 事务提交后才放行。单写线程通过有界队列合并并发更新，避免每包重写整个节点的统计文件；提交失败拒绝转发，`traffic.json` 仅保留兼容快照。首次导入旧快照与初始化标记在同一事务完成，后续恢复不再读取旧快照覆盖账本。同步提交增加了磁盘延迟，吞吐需结合实际存储测试；没有按未来流量扩大预扣。崩溃发生在提交与转发之间时，已计入的载荷可能尚未送达，因此仍不是远端收妥计费。

到额后不再接受新载荷，已获准的载荷持有收尾凭据直至提交及发送完成，避免额度通知或反向转发报错提前取消最后一块；收尾上限为 5 秒。到期、停用与存储提交失败不等待收尾。备份恢复需停机保留完整 Agent 数据目录，包含 `traffic.db` 及存在的 `traffic.db-wal`，旧 JSON 快照不能替代权威账本；进程强杀验证不代表已验证硬件断电。

核心异常退出使 Agent 关闭其所属组件并非零退出，由标准安装中已有的 systemd 失败重启策略恢复已应用配置；Agent 本身不另设一套重启循环。

SOCKS5 UDP 不再以同 IP 的任意已认证连接授权固定 UDP 入口。每个成功 `UDP ASSOCIATE` 分配独立公网动态端口，锁定来源 IP 与首个有效包的源端口，并随控制 TCP 关闭；部署需允许系统临时端口范围的 UDP 入站。原生 UDP 包没有身份字段，首包前泄露中继端口仍可能被同 IP 客户端抢占，因此这一关联机制不等于逐包密码认证。

## 运营总览

默认入口为「总览」，展示服务器 CPU、内存、根文件系统磁盘及网卡速率，汇总逐代理用量、余量、网速、期限和报价。网卡统计与代理计费口径分别展示。代理列表支持名称、客户、服务器、地址、端口搜索及协议、状态、到期和低余量筛选；选中当前结果可执行批量运营操作。

每条代理独立关联客户和月付、季付、年付报价。运营方确认线下收款后登记实收并开通或续费，历史收款记录保留当次信息；没有客户登录账号或在线支付。

## 客户端交付

Mihomo 节点配置要求明确的类型、服务器、端口及唯一名称，UDP 支持需要相应字段。[Mihomo 节点通用字段](https://wiki.metacubex.one/en/config/proxies/)

本项目提供完整配置与节点片段两种导出；独立订阅只读取已应用快照，并支持撤销。二维码由浏览器本地生成。兼容测试使用校验过的 [Mihomo v1.19.32](https://github.com/MetaCubeX/mihomo/releases/tag/v1.19.32)，将导出配置用于实际请求，不以 YAML 能解析作为唯一验收条件。

`/query` 提供免登录的只读查询。代理配置中的端点和凭据，或单条代理的私密查询链接，是查询该代理的持有证明；它们不授予同客户其他代理或内部档案的访问权。整份 Mihomo 配置只解析其中最多 100 个实际节点，不抓取外部 provider。查询结果展示统一续费联系入口，由运营方人工完成收款续期。

## 安全与运行边界

Passkey 使用锁定版本的 webauthn-rs；该库的 Passkey 注册和认证流程要求用户验证。[Webauthn API](https://docs.rs/webauthn-rs/0.5.5/webauthn_rs/struct.Webauthn.html)

本项目保留单管理员模式，密钥、TOTP 与恢复码完成传统登录；Passkey 是经过设备验证的替代登录方式。域名绑定、短时单次挑战、凭据撤销和服务器本地恢复均有明确操作入口。出租管理按代理独立计额和到期，不提供跨代理共享套餐、客户登录账号、在线支付或自动故障切换。

网站由 Agent 提供独立 HTTP(S) 监听和 WebSocket 转发，自动证书使用自己的 Certbot webroot 目录。已存在的 Nginx 和业务端口不被接管；已有控制台 HTTPS 占用 80/443 时应选择其他端口、手工证书或另一台入口机器。

完整支持范围、计量口径与操作截图见[使用手册](../README.md)。
